## 3. Chrome 中 Gemini 功能总结

Chrome 中 Gemini 的核心方向是把 Gemini 作为浏览器内的上下文助手，用户无需离开当前浏览流程即可提问、理解和处理网页信息。公开介绍重点包括：

| 能力 | 用户价值 | 对 Quill 的启示 |
| --- | --- | --- |
| 当前网页问答 | 围绕正在浏览的页面提问，减少复制粘贴 | 支持读取当前页面的可见文本并生成回答 |
| 网页摘要与要点提取 | 快速理解长文章、文档或页面 | 增加“总结当前网页”“提取要点”等动作模板 |
| 多标签页上下文 | 综合多个已打开页面进行比较、归纳 | 需要明确用户选择的标签页范围和权限提示 |
| 页面内容改写/生成 | 在浏览上下文中起草、改写或整理文字 | 与 Quill 的输入框增强、网页提示词能力天然衔接 |
| 对话式追问 | 在一次任务中连续追问，保留对话上下文 | Quill 需要定义会话生命周期、上下文大小和清除入口 |
| 浏览器内侧边栏体验 | 侧边栏与网页并存，结果不打断当前页面 | 可复用现有 Chrome Side Panel 和页面元素选择器 |

以下内容不应在本需求中默认承诺：所有用户、地区或 Chrome 版本均可用；所有网页均可读取；Gemini 的具体模型、配额、联网能力、账号要求和数据保留策略。上线前必须以官方文档和实际账号能力为准。

## 4. 需求背景（5W1H）

- **Who**：需要阅读、比较、撰写网页内容的知识工作者。
- **What**：在当前网页或选定标签页上调用 Gemini 风格的上下文 AI，并将结果用于输入框。
- **Why**：当前 Quill 主要围绕输入框执行固定动作，用户仍需手动复制网页内容，跨页面理解成本高。
- **When/Where**：用户在普通 `http/https` 页面打开 Quill 侧边栏或输入框操作面板时。
- **How**：由用户显式选择当前页面、选中内容或指定标签页，生成上下文后调用已配置模型，结果可复制、插入或继续追问。

## 5. 需求范围

### 5.1 本期包含

1. 当前页面内容摘要、要点提取、问答和改写。
2. 用户选中文本作为优先上下文；未选择时允许读取当前页面可见文本。
3. 通过现有侧边栏展示对话与结果。
4. 结果复制、插入当前输入框、重新生成和清空会话。
5. 明确的权限、读取范围、失败和内容过长提示。
6. 新功能统一命名为“与页面对话”。

### 5.2 本期不包含

1. 自动读取所有标签页或后台持续监控网页。
2. 代替 Gemini 官方账号体系、计费、模型路由或联网搜索能力。
3. 自动提交表单、自动点击网页按钮或代表用户执行高风险操作。
4. 对 `chrome://`、扩展页、浏览器新标签页等不可注入页面提供脚本注入能力。
5. 首次打开侧边栏时自动启动“与页面对话”。

## 6. 功能详细说明

### 6.1 入口与上下文选择

| 元素 | 要求 |
| --- | --- |
| 侧边栏入口 | 在现有侧边栏齿轮按钮下方增加“与页面对话”按钮；默认关闭，不自动打开 |
| 功能切换 | 点击按钮后，在现有动作区域切换为独立的页面对话界面；再次点击可返回现有动作区域 |
| 页面布局 | 对话界面参考 Chrome Gemini：展示当前页面上下文、消息列表、输入框、发送和清空会话操作 |
| 上下文范围 | 默认当前页面；提供“选中文本”“当前页面”两种明确状态 |
| 读取提示 | 首次读取前展示页面地址、预计文本范围和隐私提示 |
| 内容采集 | 优先读取用户选中文本，其次读取页面可见文本；过滤脚本、样式、隐藏节点和密码字段 |
| 长度限制 | 超出模型上下文限制时分段或提示用户缩小范围；具体阈值待模型配置确定 |

### 6.2 任务动作

首期提供：总结网页、提取要点、回答问题、改写为专业表达、生成可粘贴回复。动作应允许使用现有自定义网页提示词机制配置名称和 Prompt。

### 6.3 对话与结果

- 用户发送问题后展示进行中、成功、失败三种状态。
- 成功结果支持复制、插入当前输入框、重新生成。
- 追问沿用当前会话上下文；用户点击“清空会话”后删除本地会话内容。
- 页面切换时默认结束当前页面会话，避免上下文串页；是否保留历史待评审确认。

### 6.4 权限与禁用规则

- 仅在普通 `http/https` 页面启用网页读取和脚本注入入口。
- 沿用现有页面级/网站级禁用规则；被禁用时隐藏网页读取入口并显示原因。
- 不读取密码输入框、支付信息和隐藏字段。
- 读取失败、跨域 iframe 不可访问或页面为空时，显示可操作的降级提示。

### 6.5 数据与接口

- 使用现有 background 消息通道调用模型，新增请求类型建议为 `WEB_CONTEXT_QUERY`。
- 请求至少包含：`taskPrompt`、`pageUrl`、`pageTitle`、`selectedText`、`pageText`、`conversationId`。
- API Key、模型配置和会话数据默认只保存在本机 `chrome.storage.local/session`；不得写入日志。
- 发送前对 URL、页面文本和用户输入做长度限制及敏感字段过滤。

### 6.6 独立实现约束

- “与页面对话”必须使用独立的 TSX 文件/组件实现，建议入口为 `src/sidepanel/page-chat/PageChat.tsx`。
- 对话组件只负责界面状态、上下文展示、消息发送和结果操作；动作编辑、网页提示词和元数据编辑逻辑不得直接混入该组件。
- 通过明确的 props/callback 或独立消息服务与侧边栏宿主集成，避免复用现有 `render()` 中的大段字符串模板。
- 对话组件应具备独立测试入口，至少覆盖默认关闭、打开/返回、发送中、成功、失败、清空会话和禁用页面状态。

## 7. 性能指标

| 指标 | 目标 |
| --- | --- |
| 侧边栏首次可交互 | 本地页面打开后 1 秒内 |
| 页面文本采集 | 常规页面 2 秒内完成；超时可取消 |
| 首字响应 | 由模型服务决定，客户端展示等待状态，不阻塞页面 |
| 页面注入影响 | 不显著增加输入框交互延迟；禁用页面不得创建注入按钮 |

## 8. 非功能需求

- 隐私：默认显式触发、最小范围读取、敏感字段过滤、提供清空会话入口。
- 安全：不执行模型返回的脚本，不将网页内容拼入可执行 HTML；结果插入使用安全文本 API。
- 兼容：Chrome Manifest V3、现有 Side Panel、页面级/网站级禁用规则和自定义动作保持兼容。
- 可访问性：按钮、状态、错误信息具备可读标签；支持键盘操作和焦点顺序。

## 10. 项目规划

1. 需求评审：确认 Gemini 官方能力、地区/账号限制、上下文范围和历史策略。
2. 技术设计：完成页面采集、消息协议、上下文裁剪和错误码设计。
3. 开发：侧栏 UI、content script 采集、background 调用和安全过滤。
4. 验证：普通网页、长页面、选中文本、不可访问页面、禁用规则和模型失败场景。
5. 灰度：先对已配置模型的内部用户开放，观察耗时、失败率和内容泄露风险。

## 11. 验收标准

- 用户可在普通网页打开网页 AI，明确看到当前上下文范围。
- 选中文本时只使用选中文本作为主要上下文；未选择时可读取当前页面可见文本。
- 总结、问答、改写至少各有一个可执行动作，结果可复制或插入当前输入框。
- 页面级/网站级禁用规则生效时，不读取页面、不注入按钮，并显示原因。
- `chrome://` 等非普通页面入口禁用且无报错。
- 超长、空页面、跨域 iframe、模型错误均有明确提示和取消路径。
- 自动化测试覆盖消息协议、上下文过滤、长度裁剪、禁用规则和会话清理。
- 侧边栏首次打开时“与页面对话”不自动展开；点击齿轮下方按钮后才显示对话界面。
- 对话界面由独立 TSX 文件实现，与现有动作编辑逻辑保持模块边界。
- 对话界面参考 Chrome Gemini 的侧边栏交互：上下文明确、消息可追问、状态可见、结果可清空。
